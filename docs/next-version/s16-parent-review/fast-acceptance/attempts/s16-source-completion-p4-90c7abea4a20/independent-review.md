## 未通过的关键内容

### 1. empty 漏检见证与自己的反例矛盾

final `/assertion_checks/0/missed` 声称错误实现“清空所有输出”，在测试输入 `[]` 给 `actual=[]`；但反例输入 `[' Alice ']` 的 actual 却给 `[' Alice ']`。同一个始终清空输出的实现对反例也只能返回 `[]`。这里不是 expected/actual 字面值相等性问题，而是模型声称的行为无法产生所列反例。初判也存在这个冲突，最终没有纠正。

同记录 detected 的“如对 [] 外其他输入过滤后仍返回元素”只描述别的输入，不能推导在被检验输入 `[]` 上返回 `[' ']`。若主张添加固定元素，应明确该具体错误行为；当前说明不足以建立其写出的观察值。

### 2. 将 empty 的覆盖局限认定为零辨别力

### 3. 未纠正子报告“缺少重复保留直接覆盖”

advisory 首段同时声称“测试也缺少顺序与重复保留的直接覆盖”。final `/comparisons/0` 只抽取前半句“实现不满足契约/未裁剪过滤”并判正确，漏掉同段这个关键覆盖主张；其余比较也没有纠正这一点。

initial detected 声称 `values.sort()` 或原地 trim，却列 `actual=['X']`；这两个操作不会把两元素输入变成该单元素值。final 改成“原地 trim/修改输入”并列 `actual=['A','A']`，仍未说明将原空格元素写成 `'A'` 的具体操作。纯原地 trim 应得 `['A','']`，而不是所列值。断言能够检测改动这一结论是对的，但其要求的具体 faulty behavior → actual 见证没有落实；不能替模型补造操作来算通过。
