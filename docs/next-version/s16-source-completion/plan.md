## 目标和流程

让来源调查子任务实际收到自身指令，按只读任务执行，在必要来源缺失时不会直接以正常完成结束，并交付可核对的分析。

按 ask-matt 的路由，从已有诊断收敛为本地修复规格，后续逐段实现、测试、独立审查。编写计划时用户只要求 plan；随后已批准本地实施和验证。无需重新访谈或建立 issue tracker，不执行 to-spec 中的对外发布步骤。

实施阶段优先从上述冻结候选继续，先核对现有 worktree 与改动；不能以主工作区旧 HEAD 加大量未提交文件冒充候选。每段遵循项目要求：必要契约调整 → Feature 内实现和局部测试 → 根组合与集成测试 → 独立审查。只同步受影响契约。

## 冻结的设计决定

1. **指令归属明确。** `AgentDefinition.instructions` 进入实际子请求的受约束角色段，objective 保留为本次任务输入。Host 规则、项目规则、权限及工具限制继续生效；角色指令不扩权，也不覆盖用户约束。共享 AGENTS 保留共同约束，S16 父任务委派流程移到父任务输入，子目标放在子任务输入。
2. **修复分类器，不靠改写样例绕开错误。** 原始含 `read-only` 的真实 prompt 必须被公开启动入口冻结为 analyze。只在新任务边界使用修正结果，不能悄悄改写旧持久任务 intent。
3. **能力是否可用以当前 schema 为准。** 已有完整 read schema 就直接使用；尚未披露的能力继续走现有披露流程。S16 去掉强制加载 read 的步骤，保留确有必要的 delegate_agent 披露。旧失败原样保留。
4. **完成检查分两层。** 运行时只确定性检查明确要求的来源读取；实际分析交付、逻辑正确性与引用正确性由真实验收和独立审查检查。读齐不等于答对，模型说完成不产生 verified。
5. **只增加一个可选的必要来源集合。** 来源调查委派可显式声明必要 workspace 相对路径，在子启动时冻结。具体四个文件只属于 S16 样例；通用引擎不硬编码它们。旧调用缺省为空，保留既有普通问答、非来源任务的结束行为。
6. **有界纠正。** 来源缺失而模型返回无工具文本时，现有引擎发送包含缺失路径的 Host 反馈并在原预算内续轮；反馈后仍无新的必要来源读取进展，则明确未完成。取消、超时、硬预算优先，不另起子任务、不扩大额度、不无限重试。
7. **保持团队闭环所需的初始共享租约。** 实施中公开入口复现：只读意图修正使原 v7 的 STANDARD 12轮/30工具变成 QUICK 4轮/8工具，子读齐后父最终答复未发送。新任务以已有冻结 `agent_topology=team` 选择至少 STANDARD；原显式 deep 优先，single/旧缺 topology 的分析仍 QUICK。显式 team 的简单问答也适用这个团队最低租约，不宣称按文字精确判断复杂度。硬额度、child 不能自行续父租约、已有预算不迁移均保持；不在验收脚本里注入更大预算。该关联修正已由独审复现、Root 放行，证据见 `p3-review-checklist.md`。

## 实施顺序与阶段门

| 阶段 | 工作 | 放行标准 |
|---|---|---|
| P0 固定失败与测试入口 | 将已有失败固化为公开生产链路回归用例，记录 before | 捕获指令缺失、read-only 误分类、零读取提前结束；旧失败不能因修改断言变绿 |
| P1 修复指令传递与只读分类 | 补通子指令进入上下文的路径；修正只读表达识别 | 实际 prepared body 含角色指令；真实 prompt 冻结 analyze；权限和修改任务行为不回退 |
| P2 简化来源样例流程 | 拆开父子职责，删除已可用 read 的冗余加载要求 | 子第一轮已有 read schema，无父委派职责；未披露工具仍受原规则约束 |
| P3 增加来源完成检查 | 冻结必要来源，记录子线程成功读取，在无工具结束前检查 | 原 v7 回放不再以零读取正常完成；读齐后可结束；仍缺项准确返回未完成 |
| P4 medium 真实复验 | 冻结新候选与新样例，离线预检后真实运行一次并独审 | 来源、实际输入覆盖、分析、引用、终态、用量分别达标；任何失败保持原结果 |

P0–P3 每阶段在相关测试和独立审查通过后进入下一阶段；审查读真实 diff 和反例，不仅阅读报告。P4 失败后诊断本次原因，不自动切 high 或反复试到通过。

## P0：测试入口

主验收入口采用公开父任务启动 → 原委派 dispatcher → 原生产 child factory → 原 AgentEngine → 原 ChildResult 的完整链路。模型客户端用可编排事件流替换，保留生产上下文、工具筛选、授权和终态处理；不把纯 helper 单测当作集成成功。

已有 `replay.py` 是快速失败证据，使用内存会话/context/action 替身，不能单独证明生产组装正确。它继续保留用于定点回放。

至少固定以下反例：

- 自定义 agent 声明唯一角色指令，prepared body 必须包含它；另一个子任务不能继承前一个角色。
- v7 原始父 prompt 必须为 analyze；`read only`、`readonly` 和明确修改指令保持各自行为。
- 原始“披露后下一轮会读”的模型流，在缺少必要来源时不能直接完成。

## P1：确定性缺陷修复

### 指令传递

贯通 orchestration 中的 AgentDefinition → Host child factory → context builder。角色指令走明确的上下文参数，不拼接成伪造 user 历史；在首次请求、工具续轮和上下文恢复中保持一致。

测试自定义及内置只读角色；检查父子之间、两个子任务之间无指令串用。即使角色指令要求写入，原只读权限仍阻断写工具。

### 只读分类

对只读表达作局部、明确的规范化或匹配，支持普通连字符及相关常用连字符形式；不扩大成任意字符串含 read 就为只读。增加带否定命令和文件名的反例，检查明确的修改请求未被降成 analyze。

公开任务结果允许 analyze 在 unchanged/unverified 情况下正常结束；不再出现与该目标无关的“必须修改文件”阻塞。修复与 TaskAuthorization 分离，识别为 analyze 不代表新增任何能力。

## P2：样例和提示简化

共享规则仅保留工作区边界、只读约束和当前/历史文档的身份。父任务输入负责委派与核对，子任务输入负责读取与分析。

直接使用实际已提供的 read schema。对真正需要延迟披露的能力，仅澄清“后续模型请求可用”，不能将用户下一条消息作为前置条件；不改变 schema digest、可用性和权限检查。

不把预期行为答案、正确行号或验收金标准写进模型提示。新样例的指令变化逐条记录；保留 v7 原始样例和日志。

## P3：最小来源完成契约

### 数据与职责

- 在现有 ChildRunRequest/委派输入中增加向后兼容的可选必要来源集合；来源路径须通过现有 workspace 路径约束，数量有界，启动后模型不能削减。
- S16 明确声明四份原始文本文件。委派预检和实际调用核对该集合；遗漏或漂移应明确失败，不能静默进入无检查的子运行。
- 用已有调用参数和持久事件保存要求与读取事实，优先避免新增数据库表及第二套任务状态库。若无法依现有记录可靠恢复，先反馈契约缺口再调整设计。
- 只认当前子线程的成功读取回执和完整文本结果；路径声明、工具披露、失败/截断读取、父线程补读均不能填补缺项。此版本针对明确要求完整文件读取的子任务，repo map 摘要和局部 slices 不冒充完整文件读取。
- Core 只消费有类型的要求和读取事实，Host 负责工具身份与路径适配；不得让 Core 直接读文件或具体 SQLite。

### 结束行为

1. 无来源要求：保留既有正常结束行为。
2. 有缺失来源且尚可执行：现有 runtime notice 告知具体缺项，继续同一子运行；轮数、工具、时间和 token 全部照常计费。
3. 反馈后模型仍只返回文本、未增加必要来源证据：返回现有 failed 状态，明确 `source_requirements_unmet` 和 remaining 路径；该状态表示此子目标未完成，不冒充 Provider 错误。
4. 来源读齐且已有最终答复：允许正常运行终态，verification 仍不升级；分析内容是否有效由 P4 独审。
5. 取消、硬预算或超时：保留原对应终态和未结算用量，不用缺来源错误覆盖。

声明来源要求的子任务还须确定性拒绝空白最终答复；纠正前的长计划不能挤掉最终分析，父侧 advisory 取最后一条非空、无工具调用的最终答复并保留既有长度上限。无来源要求任务保持原聚合行为；这些检查不判断自然语言语义。

检查放在现有单引擎无工具结束分支，复用 runtime notice、事件和结果投影。不得在外层重启 child 来绕过终态或预算。

### 必须覆盖的反例

零读取、只读部分、重复同一文件、错误路径、读取失败、截断内容、只加载 schema、父读齐而子未读、来源全齐、普通无来源要求任务、纠正期间取消、预算耗尽，以及恢复后不能丢失冻结要求或重置纠正边界。

“来源已齐但回答只有计划”仍须在独立交付检查中 FAIL；不使用自然语言关键词匹配伪装可靠的语义验证。这一层界限必须写进阶段报告。

## P4：同条件 medium 复验

“同条件”指模型、effort、来源内容、预算、期限和质量标准与 v7 一致；生产代码为修复后的新候选，提示仅含计划内修改，不声称与 v7 输入逐字节一致。

| 项目 | 固定值 |
|---|---|
| 模型与 effort | GLM5.3-flash / medium，父子均核对实际发送值 |
| 累计 token | 父 1,000,000；子 300,000 |
| 单 prompt / 工具 schema / output | 300,000 / 20,000 / 4,096 |
| 回合与工具 | 共享 12 轮 / 40 工具；子上限仍 5 工具；每轮上限 8 |
| 初始软租约 | STANDARD 12 轮 / 30 工具，与原 v7 实际账本一致；由自然公开启动选择，不由 harness 改写 |
| 时限 | 子 240 秒；父 watchdog 880 秒；总样例 900 秒 |
| 原始来源 | 与 v7 四文件 hash 一致，保持只读 |
| Provider transport | 保持 timeout 60 秒、max_retries 2，并记录实际请求次数 |

先完成零 Provider 的公开入口预检，确认实际请求中的角色指令、read schema、来源要求、父 intent 和预算。再为新样例冻结候选 SHA 与输出目录，实际运行一次；旧 owned、失败和 unknown usage 不覆盖。

独立审查逐项判断：

- 子实际完成四份读取，完整来源进入分析前实际发送的请求；父读取不能替代子证据。
- 子交付实际分析，区分 current/legacy；父核对得到正确的五项行为结论。
- path:line 与物理行号相符；不声称运行了未执行的测试。
- 父结束符合 analyze 目标，子没有凭文本伪造验证；来源完成与 verified 严格区分。
- 当前请求用量唯一且完整结算；如仍有 unknown 则保留并按该项失败处理，旧未知负债单列。

一次通过仅补此有界来源子任务门，不能推导一般长调查、模型稳定成功率或所有 S16 门通过。最终 S16 状态仍按原总验收矩阵逐项核对。

## 预计修改边界与验证

涉及已有 Core、Context、Orchestration Feature，以及必要 Host 组合和 S16 样例。优先保持在既有 Units 内完成；不新增通用工作流平台、额外模型裁判、high 路由、自动发布流程。

局部回归优先用现有 production child factory、child result、completion/intent、tool disclosure 和 prepared-request 测试入口。P3 涉及共享结束分支，需同时覆盖普通父任务、只读子任务与修改任务，随后运行项目全量测试入口。最终候选准备交付时核对五平台 CI，不把旧候选 CI 当作新源码通过。

最终交付：修复 diff、相关契约更新、失败转绿的生产链路测试、原失败与新真实记录的对照、独立审查结论，以及 S16 验收矩阵的准确更新。
