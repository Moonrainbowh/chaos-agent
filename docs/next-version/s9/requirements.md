# S9 当前阶段需求与边界

S8 独立PASS后进入；不同时开发S10。以S8候选为基线，原用户authentication及数据不动。本阶段不提交/推送、真实Host/Provider不启动。

Core继续唯一事件循环和既有监督/预算接口。正文、工具名字、空换窗、耗时或新错误不应重置停滞/续租。Host可核的generation/subject、真实新验证、原失败解决、与冻结目标或成功搜索返回路径有关的新信息才可候选续租；软租约仍受原max renewals和硬预算。有限新读取候选允许连续无正文调查，不冒称需求已完成。

失败/停滞先提供具体原因及修复方向，再在现有边界暂停，避免重复守卫给互斥结论。复用S3原调用配对/规范操作与S6执行、变更、验证分层；不新建通用进度平台/第二监督器/调度器。

验证根据任务和可信变更风险选择已有相关轻量或严格计划；普通shell exit0不是所有需求证据。无需修改要保可说明结果，但模型正文不能单独制造系统证据或降级冻结标准。保持未验证/环境受阻/失败/真实通过分开。

验收：实际默认生产装配的长只读、多文件连续编辑、有效重读能继续；重复调用/失败加正文、空换窗、换别名或噪声不能绕过；未知副作用恢复门和实际用量/owner收尾仍正确。自测后冻结差异，全量与独立监督放行再进S10。
