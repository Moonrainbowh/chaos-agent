## 第一性原理与定位

测试辨别力需要依次成立：明确同一个候选错误行为；从代码推导这个行为在指定输入的观察；按原断言比较观察与期望；最后只对这个见证陈述检测/漏检结论。另一个输入的契约反例必须属于同一个候选行为。一个通过样例不能证明没有任何辨别力。

此前的v3已补上字面值比较检查，生产复验五个当前结果正确且中文恢复。但GLM仍会把候选描述改成另一种行为，或在子报告比较时漏掉同段另一句错误主张。此时继续只补JSON字段/提示词，不能给行为→观察的正确性作保证。

## 三种实际诊断

1. [职责拆分探针](consistency-probe-90c7/review.md)：一次核对fault/观察，一次拆原子主张核对覆盖。2次请求，67.850秒，10129 tokens。仍把“清空所有输出”改成“不做trim”而判一致，仍认可empty零辨别力；拆分有部分帮助，整体FAIL。
2. 去掉原稿声称输出/期望/判定的 [盲推演原始结果](blind-trace-probe-90c7/result-1.json)：1次请求，17.686秒，2704 tokens。10条fault原文保持，但empty/detected和no_mutation/detected被误当真实`list(values)`；明确的清空输出又被标unknown。去掉声称结果仍未消除角色混淆，FAIL。
3. [代码化见证独审](program-witness-probe-90c7/review.md)：请求一只生成明确候选函数，不报actual；请求二只看到这些函数及新建输入，不看原实现、契约结论或声称actual。2次请求，26.020秒，3615 tokens。5个detected有效；5个missed仅1个代码能通过原断言，该记录的反例expected仍错。其余4个missed代码都会被原断言拒绝。独立推演15次调用、30个返回/输入状态观察中，28正确、2错误，整体FAIL。

代码化探针的两个具体推演错误：

- 对 `[' B ','B','c']`，候选的all-equal条件为false，普通append分支应返回 `['B','B','c']`，模型却报告 `['B','c']`。
- 对 `[' A ',' ','C']`，候选先pop移除`'C'`再清理，返回应为 `['A']`，模型却报告 `['A','C']`；它同时正确报告了调用后输入不含`C`，说明返回值与输入状态内部也不一致。

成本与质量分开：[汇总核对表](program-witness-probe-90c7/checks-review.json)记录 **5次请求、16448 tokens、111.556秒**。这是用户继续后的诊断成本，独立于90c7原生产复验的32655 tokens，不重复结算。每次调用仍GLM-5.3-flash/medium/4096，无工具；原始请求、SSE、响应、用量均保留。
