# 父复核的断言辨别力误判：根因与本轮边界

2026-10-08，沿用原 GLM-5.3-flash / medium、来源、预算和静态分析限制。不运行全量测试，不改变 fixture 或按期望答案改写模型输出。

## 第一性原理

测试 T 在输入 x 上观察实现 P，断言判断 A(observation(P,x))。判断“当前 P 是否通过 T”，和判断“T 能排除哪些违反契约的 P'”，是两个不同的问题。

- 一个违反契约且断言失败的具体实现，证明该错误行为能被检测。
- 一个违反契约但断言通过的具体实现，证明该错误行为会漏检。它不证明所有同类错误都会漏检。
- 通过用例的实现还需要一个真实契约反例，才能叫“漏检”；正确实现通过不构成覆盖缺口。

74e 实际终稿给出的 `[' A ','A']` 不等于 duplicates 断言期望 `['A','A']`，故“它能通过”直接不成立。trim 后反转得到 `['Bob','Alice']` 会被 trim 用例拒绝；trim 后排序却可能通过已有样例。因此排序漏检不能推出“没有任何顺序辨别力”。empty 断言也会拒绝 `['X']` 等返回，存在一个返回 `[]` 的实现不能证明它不检测任何错误。

## 有证据的工程根因

现有 GUIDANCE 已要求输入、期望、静态结果、检测/漏检见证及有限范围，74e 实际 wire 已携带这些指令。错误仍发生，说明重复增加同类提醒不足以修复已观察的路径。

旧校验只检查非空 judgment/rationale、引用、需求和段落覆盖。见证与比较结果没有独立表示，所以“不同值却说通过”以及“存在漏检所以零检测”都可以得到 errors=[]。结构交付门没有承诺语义证明；问题在于完成标准缺少能够检查这种低层矛盾的证据。

此前具体输出探针 36/36 正确，抽象断言范围仍有错误，支持将字面值计算和结论综合分开。独立初判在没有子报告时也出错，排除了“只有子报告污染”这一归因。模型内部机制、一般能力、提高 effort 是否有帮助均未经证明。

中文缺口是单独、明确的集成遗漏：隔离请求绕过普通上下文，却未携带已有中文交付约束；渲染器只加中文标签，不能翻译模型判断。

## 最小修复与验证边界

新任务使用 v3：两次原有请求增加紧凑 assertion_checks，记录断言引用、输入、期望、当前静态观测、可检测见证、漏检见证及契约反例。Host 仅比较普通 JSON 字面值，校验 detected 不相等、missed 相等、契约反例不相等，重算当前比较结果；scope 固定 witness_only。不能表达的断言或未确定见证保留 unknown，不能编造证明。

旧 v1/v2 快照继续原协议。补全仍只限本阶段错误字段、最多一次、原预算，不接受自由重写。正常请求和补全只披露各自实际接受的格式。最终仍为静态分析、unverified；这些检查不验证模型对源码的推演，也不自动证明自由文本全部正确，真实语义验收仍需独立复核。

定向红测先复现旧门接受错误通过见证：4 项中 3 failures、1 error（缺失 Host 计算结果）。随后只运行新增/相邻 Core 与既定三个来源复核集成模块，不运行全仓。

## 预验收口径

本轮来源复核样例既有缺口包括 duplicates、order、empty 和中文交付。修复后须由一次新的真实运行和独立复核确认，不能仅因代码已修改宣布 PASS。历史 S16 总矩阵/来源安装/跨平台结果绑定旧候选，不继承为当前 dirty 候选的总体发布证据；本轮不另加新的语义考题。
