# 手机 SSH 终端适配：串联阶段计划

日期：2026-10-03。依据：[URI Agent 手机端源码调研](uri-agent-mobile-source-review-20261003.md)、当前 `src/code_agent/interfaces/AGENTS.md` 和 `AGENTS.python.md`。用户要求按 S1 → S2 → S3 → S4 → S5 串联推进，每阶段完成后由另一位 Agent 检查，通过后进入下一阶段。

## 目标与约定

按照 URI Agent 的手机 SSH 终端方式适配 Chaos Agent：同一个 TUI、同一个执行内核，窄终端自动切换紧凑布局，关键操作支持触控。保留当前追加式消息转录和已存在的输入、命令、暂停、会话恢复语义；实现使用本项目的控制器接口。SSH 服务、连接 App 与网络入口属于部署环境，S5 核查可用条件后再实际连接。

参照上游固定提交 `7e1464216a01738e587089211824a25346de68fe` 的 `auto/wide/compact`、≤64 列自动切换、底部操作区、单击选择和小步滚动；布局方式结合当前追加式终端结构调整。Moshi 通知不属于此次任务；现有手机网页 Host 的代码不在本次修改范围。

项目的阶段映射：S1 为需求；S2、S3 为 Feature 实现；S4 为集成与回归；S5 为部署环境核查和端到端验收。S4 如发现 Feature 问题，先回到 S2/S3 的对应范围修复和复查，再恢复 S4，不在集成阶段直接改 Feature。

## S2/S3 的具体边界

- 主要修改目录：`src/code_agent/interfaces/` 及其现有 `tests/`。布局、操作区几何和命中逻辑放入职责独立的小模块；不重写 Agent loop。
- 复用入口：`terminal_tail.py` / `terminal_composer.py` 负责输入区渲染，`tui_presentation.py` 与 `windows_tui.py` 接通视图；`terminal_io.py` / `posix_terminal_io.py` 归一输入，`tui_input.py` / `tui_interactions.py` 接通操作。
- 命令入口采用项目已有命令注册与可用性机制。`/compact` 已用于上下文压缩，布局使用独立的 `/layout`（兼容 `:layout`）；不复用 `/compact`。
- 紧凑布局支持自动判定和明确手动覆盖；自动阈值参照上游为 ≤64 列。切换不会丢失草稿、附件、所选会话或当前任务。
- 鼠标命中使用最近一次绘制的几何；尺寸变化后必须更新或暂时拒绝旧几何，不允许旧点击坐标误触提交/暂停。终端控制序列不能作为正文进入输入缓冲。
- 宽屏继续遵守现有终端契约；手机紧凑模式允许有界触控操作栏，但不据此新增应用专有的永久消息历史。

## 监督与推进规则

每个阶段由主 Agent 完成实现和相称验证后，给独立监督 Agent 提供该阶段目标、实际改动及验证结果。监督 Agent 只读检查，输出“通过”“有问题”或“证据不足”，并给出文件/行号与影响；主 Agent 核实发现并更新本文件。

发现问题立即向用户说明，留在当前阶段修复并再次检查；通过后自动进入下一阶段。涉及新的目标、系统服务安装、网络部署权限或无法取得的真机环境时，只暂停依赖这些条件的工作。监督结论不能替代测试和真机物证。

本工作区已有大量未提交改动。每个实现阶段以开始时的当前文件为基线，监督聚焦该阶段的增量；不得把已有改动算成本次实现或回退已有改动。阶段顺序不允许 S3 提前实现 S4 接线，也不允许跳过监督。
