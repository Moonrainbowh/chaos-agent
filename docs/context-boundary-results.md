# 显式 Context Boundary 对照测试结果

完成 10 个固定长历史修复任务的配对测试，共 20 次真实 API 续跑。**本轮未观察到效率或错误恢复率提升；显式 boundary 总 token 增加 1.77%。**

## 核心结果

| 指标 | 普通 summary | 显式 boundary |
|---|---:|---:|
| 总 token（含交接） | 2,354,073 | 2,395,728 |
| 压缩后错误恢复 | 10/10（100%） | 10/10（100%） |
| 同路径、同内容的重复读文件 | 20 | 20 |
| API 请求 | 50 | 50 |
| 成功提交的窗口边界 | 10 | 10 |
| 缺失 usage / API 失败 | 0 / 0 | 0 / 0 |
| 实测总耗时（秒） | 485.673 | 660.595 |

耗时包含远端服务、网络和本地检查；只有单次配对重复，不能把该耗时差当成稳定的模型速度结论。缓存输入没有从上下文占用中减去，也没有在总 token 中重复相加。

显式交接多消耗 41,655 token：其中交接调用增加 9,709，后续执行增加 31,946。后续执行部分增加约 47.42%，总量只增加 1.77% 是因为长历史的首次交接输入占了大部分用量。交接文本变长、后续请求次数相同，支持“更长交接被继续带入而未减少读取/轮次”的解释。

## 测试口径与局限

- 每个任务约 230k 估算历史输入，工作窗 256000，准备 75%、换窗 87.5%，安全余量 16000，输出预留沿用 profile 的 128000，任务预算独立为 5000000。模型 profile 为 gpt56_sol，API 为 chat_completions，reasoning=low。
- 前史是确定性生成的公开审计样例及真实读文件工具产生的固定现场；随后由生产 AgentEngine、Provider adapter、动作策略、Workspace 读写和真实 API 执行修复。测试覆盖单次换窗后的续跑，不是完整真实仓库的多阶段长任务收益证明。
- 普通 summary 同样获得完整来源、相同工具和 8192 token 交接额度。没有沿用旧摘要链路的 8k 输入裁剪来削弱基线。两组每个任务的前史相同，按 AB/BA 交替串行运行。
- 隐藏用例与参考实现没有复制到执行工作区。初始文件确实不能通过隐藏检查；最终由独立进程验证行为，并检查保护文件不变。20 份最终代码已逐份检查，均为正常实现，没有导入评测代码或读取隐藏文件。
- 这些是小型契约修复，恢复率出现满分上限；只能说未观察到提升，不能证明所有任务上的恢复能力相同。尚未测试多个连续窗口、更复杂多文件工程、其他 API 或多模态。
- 重复读取定义为相同路径、相同内容版本的再次 read_file，包括固定前史中已经读过的文件；它不自动等同于无效 I/O，恢复时核对当前版本可能是合理动作。
- 此批正式样本均由阈值自动触发换窗；模型没有主动调用 new_context、context_note 或 context_history。因此本轮主要比较同等可用工具下的普通摘要与结构化交接，未测出主动笔记和按需回查的收益。
- 所有正式结果保留，没有按成绩重跑、替换任务或推广为默认。无可信网关单价，不推算货币费用。

## 机制与容量验证

- 小窗 16k、目标窗 256k 的独立 median pilot 两组都完成一次换窗并通过检查；128k 配置烟测两组也都通过。pilot 与正式 10 任务分离，不并入主表。
- API 输入探测成功覆盖约 1k、32k、224k；计数修正后 224k 样本估算 224186、API 实测 223923，相差 263。正式 100 次请求的估算均高于实测，差值 263～1093 token。
- 当前 profile 配置 combined=400000、output=128000、safety=16000，因此请求 512k 工作窗也被有效硬上限钳制为 256k；没有自动扩展 provider 容量。此处只验证容量和机制，没有证明 256k 是质量/速度最优点。
