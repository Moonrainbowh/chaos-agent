## 已实现的三个改动

1. **宿主准备完整来源。** 对 `ANALYZE` 任务中的一次真实 `required_sources` 委派，由 Host 沿用授权 dispatcher 读取全文，保存正文哈希、物理行号和明确的宿主来源标记。缺失、截断、授权失败或容量不足均阻止正常交付。实际序列化请求包含原文；不会把宿主准备正文伪装成父模型读取回执，原有子任务来源检查继续生效。
2. **同一父任务内执行两阶段复核。** 独立初判只接收真实用户要求、完整来源及宿主约束，排除子报告、模型编写的委派说明、历史、摘要、notes 和项目记忆。比较阶段才引入完整子报告与初判；检查分歧、新增断言、内部矛盾以及双方一致的过强结论。两个请求沿用原 Provider 和任务预算，不新增审查委派。
3. **共享完成路径检查实际交付。** 内部结构检查要求覆盖、来源版本、物理行范围、引用原文、子报告段落比较及明确的未知项。正常与软额度结束共享检查，两阶段总计最多一次补全。硬预算耗尽或 Supervisor 暂停保留未完成项，不为复核续额。最终渲染中文报告，内部 JSON 不进入普通可见消息；交付记录和消息原子保存，恢复无需重做已交付复核。

结构检查确认的是可观察的流程事实，不证明自然语言结论为真。合法的只读交付保持 `completed / unverified`；不执行被测任务禁止的命令或测试。当前范围限于上述单次明确来源委派，不把多个委派静默合并成一次完整复核。

主要实现位于 [Host 来源准备](../../../chaos_agent/parent_review.py)、[复核结构与请求](../../../src/code_agent/core/parent_review.py)、[共享交付门](../../../src/code_agent/core/_engine_parent_review.py)，以及对应 Engine、Sessions 装配与持久化接口。

## 固定模型的局部语义对照

实施与独审子 agent 按用户要求使用 **GPT-6.1-sol / medium**；被测模型继续固定 **GLM-5.3-flash / medium**，两种角色没有混用。

三种预先冻结案例 × A/B 两组 × 两阶段，共 **12 次实际请求**，无重试、失败替换或重新取样。A 提前看到子报告，B 延后看到；两组预算上限一致。实际消耗 **33,460 tokens**（输入 18,069，输出 15,391；其中 reasoning 1,976 已包含在输出中）。

**六组都未达到完整语义复核通过。** 五项行为契约字段共 60/60 正确，但测试辨别能力、报告纠正和引用仍有错误。尤其原案例 B 的独立阶段尚未看到子报告，就已错误认为空输入测试不能区分违规实现；第二阶段也没有纠正。因此本轮不能证明隔离消除了原错误，或 B 优于 A。

冻结实验要求严格 JSON，12 份输出全部带代码围栏，原始评分保留 `UNPARSEABLE_PRESERVED`；人工审查另行读取完整输出，没有修复后重算通过。生产交付门独立支持单个规范 JSON 围栏，这不改变实验冻结判据。事后还发现预设“正确报告”中的一条非 list 返回值描述过宽，已登记设计限制，没有修改输入重跑。

完整证据见 [语义审查](semantic-review.md)、[统计结果](semantic-results.json) 与 [实际请求清单](semantic-run-01/manifest.json)。开发侧 oracle 已将“不修改输入”和“返回不同对象”拆开；执行反例得到的证据没有注入被测模型，也没有伪装成模型执行结果。
