# 父复核编排修复

基线：`b28868a`，工作分支：`codex/s16-parent-review`。本次实施依据用户提供的父复核方案；保留之前的角色指令传递、只读意图分类和 ChildSourceCompletion。

## 修改边界

1. 对明确列出来源的只读委派，由 Host 通过既有授权读取接口准备完整原文，固定版本和物理行号。缺失、截断和授权失败不得当作完整来源；Host 准备正文不伪造父模型读取回执。
2. 同一父任务中执行两个实际模型请求。独立阶段只接收原始任务、来源和必要宿主约束，不接收子报告、历史摘要、笔记或项目记忆。比较阶段接收同一来源、初判与子报告，检查差异、新增断言、内部矛盾以及双方一致的强断言。
3. 共享终结路径检查任务覆盖、引用关联、比较和未知项。一次补全机会受原预算约束，不能续额。缺项使用既有 remaining/stop_code 表达；完整交付仍保留 unverified。

不更改被测任务的一次委派限制，不允许它执行命令或测试，不把开发侧反例当作模型取得的证据，不把结构完整当作语义正确。

## 验证

- 先以脚本 Provider 的实际请求装配复现缺口，再检查两阶段隔离、完整来源、缺项补全、正常与软额度结束、预算计数和恢复行为。
- 保留来源回执相关回归。核心预算和终结行为涉及共享路径，完成局部测试后在 Windows / Python 3.13.7 运行项目全量入口。
- 开发侧修正“不修改输入”的 oracle：仅比较输入调用前后；另记是否返回不同对象，不将后者擅自加入验收条件。
- 局部语义对照固定 GLM5.3-flash / medium，三种预先冻结的正确、错误和部分正确子报告；A/B 都有两阶段且同预算，最多十二次外部请求，不失败重抽、不替换模型。保留所有请求、输出、usage 与失败；局部对照不等于生产 S16 整链验收。

实施与独审子 agent 使用用户指定的 `gpt-6.1-sol / medium`，与被测模型分别记录。
