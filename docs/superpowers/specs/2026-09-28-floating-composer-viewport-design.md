# 历史消息视口与底部悬浮输入区设计

## 目标

在 Windows Terminal TUI 中把历史消息区和输入区分成两个由应用管理的区域：输入区始终停靠在当前终端视口底部；用户在历史消息中间按 Space 也能展开输入区；输入、展开、收起和滚轮浏览都不把消息视口强制跳回最新消息。

## 边界

- 保留现有追加式会话、消息状态、输入草稿、粘贴和提交语义。
- 只改变 TUI 的视口、滚动输入和动态尾部绘制，不改变持久化消息或任务状态机。
- 原生 Windows Terminal 文本选择仍由终端负责；应用只接管滚轮、翻页、Home/End 等导航键。
- 非交互输出、JSON/CLI 模式和无 TTY 模式不启用该视口。

## 方案

应用维护一个有界的历史行缓冲和 `viewport_offset`。历史条目继续通过现有可信渲染器生成，但不再依赖终端原生 scrollback 作为消息视口。每次绘制时：

1. 根据终端宽度把当前转录渲染为历史行。
2. 按视口偏移截取可见历史行。
3. 在视口底部预留 Composer 和状态栏的高度。
4. 用绝对光标定位重绘可见历史、输入区和状态栏，避免追加输出改变视口。

视口位于底部时，新消息和流式增量继续跟随最新内容；用户向上滚动后，新增消息只更新数据和底部提示，不改变 `viewport_offset`。按 Space 只切换 Composer 展开状态，并以当前视口为基准重绘。

## 输入与滚动

- 启用终端鼠标报告，仅消费垂直滚轮事件并映射为 `page_up`/`page_down` 级别的有界滚动；退出时恢复终端模式。
- 保留现有键盘 `page_up`、`page_down`、`home`、`end` 行为，并将它们作用于历史视口而非输入草稿；输入区内部编辑键仍由 Composer 处理。
- `Space` 在折叠状态无论当前视口位置都展开 Composer；展开状态的 Space 继续输入空格。
- `Esc` 只收起 Composer 并保留草稿；当 Composer 已折叠时保留现有暂停/退出语义。
- 视口偏移始终夹在 `[0, max_offset]`，历史不足时不产生空白滚动区。

## 重绘与兼容

- 通过一次受控的全屏区域重绘替代局部尾部回滚，避免输入框被写入滚动历史后再次滚走。
- 保留当前主题、颜色、Markdown、附件标记、状态栏和窄屏裁剪规则。
- resize、清屏、恢复会话、完成态折叠和退出都重置或重新计算视口状态；不会重复历史消息。
- 非 Windows 或无法启用鼠标报告时，键盘滚动仍可用；无法建立应用视口时回退到现有尾部渲染，不伪造悬浮效果。

## 验证

- 单元测试覆盖：历史中间按 Space、展开后滚轮/翻页不跳底、底部跟随新消息、输入草稿在滚动和收起后保留、视口边界和 resize。
- Windows Terminal 手工验证：任务完成后滚到问题上方，按 Space，输入 `1`/`2`/`3`，滚轮查看历史，确认输入框仍在底部且历史位置不变；回到底部后确认新消息正常跟随。
- 运行现有 Interfaces 测试集和新增视口测试。
